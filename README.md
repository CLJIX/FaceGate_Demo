# 人脸门禁 Demo（单目 RGB 摄像头 + 多线索活体检测）

一个跑在 Windows 本地的人脸门禁教学 Demo。它只用一个普通 RGB 摄像头，不依赖红外、
深度相机或任何专用门禁硬件，完成人脸录入、删除、活体检测、身份判定和开门模拟。

与常见的人脸识别 Demo 不同，这个项目的重心不在「认出是谁」，而在**把活体检测的
内部参数和中间图像全部摊开给你看**：每一帧的 FFT 幅度谱、Laplacian 纹理响应、
单应拟合残差、眼睛开合比、姿态角、七路线索的原始读数与融合过程，都实时画在同一块
面板上。它的目标是让你能对着画面读懂「单镜头是怎么判断眼前是真人还是一张照片/一块屏幕的」。

---

## 一、它能做什么，不能做什么

能做的：

- 从摄像头采集人脸，提取 512 维特征存入本地人脸库，支持自定义姓名或 ID；
- 按 ID / 姓名删除指定人脸，或清空整个人脸库（清空前自动备份）；
- 识别照片、屏幕翻拍、视频回放这类常见呈现攻击，输出「是本人 / 不是本人 / 非活体 / 未录入」；
- 判定通过时在终端打印「开门」并在界面上给出开门状态，不接真实门锁；
- 把每帧全部原始指标写入 CSV，便于离线画分布、重新标定阈值。

明确不做的：多人权限管理、云端服务、移动端或嵌入式部署、真实门锁驱动。

## 二、环境要求与安装

要求 Windows 10/11、Python 3.10 及以上（本项目在 Python 3.14 + onnxruntime 1.31 上验证）、
一个普通 USB 或内置摄像头。全部推理在 CPU 上完成，无需 GPU。

```bat
cd /d E:\人脸识别Demo

:: 1. 建虚拟环境（Python 3.14 下 insightface 2.1 提供纯 Python 轮子，无需编译）
py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip

:: 2. 安装依赖
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: 3. 自检：检查依赖、摄像头，并标定活体阈值
.venv\Scripts\python.exe main.py selftest
```

首次运行会自动从 GitHub 下载 insightface 的 `buffalo_l` 模型包（约 275 MB）和官方活体
模型（1.4 MB），存放在 `C:\Users\<你>\.insightface\`。下载一次后离线可用。

`selftest` 通过后会打印平面性线索的标定结果与建议阈值。换摄像头或换光照环境后重跑一次即可。

多个摄像头时用 `python main.py cameras` 列出可用序号与分辨率，启动时 `--camera <序号>`
指定；运行中按 `c` 或点工具栏「摄像头:n」按钮即可热切换（切换后活体轨迹自动重置）。

## 四、快速开始

以下命令均在项目根目录、激活虚拟环境后执行（或直接写全 `.venv\Scripts\python.exe`）。

### 4.1 录入人脸

```bat
python main.py enroll --name 张三
```

界面会提示你依次摆出几种姿态（正面、左转、右转、抬头、低头），每采集到一条合格样本
会在终端打印该样本的姿态角与质量分。采集满 `gallery.samples_per_person`（默认 5）条即完成。

录入有四道门槛，任何一条不满足都会把原因直接显示在界面上：

1. 人脸框短边不小于 `gallery.min_face_px`（默认 90 px），太小则特征质量差；
2. 检测置信度不低于 `gallery.min_det_score`；
3. **必须通过活体检测**（`gallery.require_live`，默认开）——否则一张照片就能进库；
4. 新样本与已有样本的余弦相似度不得高于 `gallery.max_pairwise_sim`（默认 0.92），
   姿态重复的样本没有信息量，会被丢弃并提示换角度。

也可以在识别界面里按 `e` 键就地录入：弹出系统输入框（支持中文输入法）填写姓名后进入
采集循环，界面上实时显示采集进度和每一条被拒的原因。

### 4.2 实时识别（门禁主流程）

```bat
python main.py recognize
```

打开 1210×680 的调试窗口。正对摄像头并缓慢左右转头，几秒后界面给出判定：

| 判定 | 含义 | 触发条件 |
|---|---|---|
| 是本人 | 开门 | 活体通过 且 最高相似度 ≥ `gate.accept_threshold`（默认 0.42） |
| 不是本人 | 拒绝 | 活体通过 但相似度落在陌生人线与开门线之间 |
| 非活体 | 拒绝 | 活体融合分低于阈值，或某条线索触发一票否决 |
| 未录入 | 提示去录入 | 人脸库为空，或最高相似度低于 `gate.stranger_threshold`（默认 0.16） |
| 观察中 | 等待 | 活体证据还没攒够（轨迹太短或头没动） |

判定为「是本人」时终端会打印一行绿色的 `>>> 开门 <<<`，界面边框变绿并保持
`gate.open_hold_sec` 秒；同一人 `gate.cooldown_sec` 秒内不会重复触发。

### 4.3 查看 / 删除 / 清空

命令行方式：

```bat
python main.py list                     :: 列出人脸库
python main.py remove --name 张三        :: 按姓名子串或 ID 删除（有确认提示）
python main.py remove --id zhangsan -y   :: 跳过确认
python main.py clear                     :: 清空全库（先自动备份到 data\gallery_backup_*）
```

图形界面方式：识别窗口里按 `m` 进入管理模式，列出所有人的缩略图、ID、样本数与每条样本的
姿态角；`↑/↓` 选择后 `d` 删除（按两次确认）、`r` 弹框改名、`c` 清空全库（按两次确认）、
`e` 录入新人，`m` 或 `ESC` 返回识别。

### 4.4 用视频做攻击测试

没有打印机和屏幕也能复现地测试反欺骗路径：

```bat
python main.py --source samples\attack_photo.mp4 recognize   :: 静止照片 → 期望「非活体」
python main.py --source samples\live_proxy.mp4  recognize    :: 眨眼+晃动代理 → 期望通过活体
python tools\make_live_proxy.py                              :: 重新生成这两份素材
```

## 五、活体检测：七路线索与两层融合

### 5.1 为什么是七路

单靠任何一个信号都拦不住所有攻击，所以按攻击方式分工：

| 线索 | 主要拦 | 物理依据 | 单帧/时间 |
|---|---|---|---|
| 官方活体 CNN | 照片/屏幕/面具 | insightface 自带 80×80 RGB 分类器，直出真人概率 | 单帧 |
| 自然眨眼 | 静置照片 | 真人 3~5 秒眨一次眼，打印件不会；用眼睛开合比（EAR）检测 | 时间 |
| 运动/形变 | 静置照片、暂停视频 | 冻结画面的全局位移与非刚性形变都趋近 0 | 时间 |
| 平面性视差 | 照片、屏幕（核心） | 平面载体的帧间映射严格是单应；三维脸不是 | 时间 |
| 高频纹理 | 屏幕翻拍 | 「显示→再拍摄」两次采样加压缩会抹掉高频细节 | 单帧 |
| 屏幕摩尔纹 | 屏幕翻拍 | 像素栅格在频域留下孤立、尖锐的周期性峰值 | 单帧 |
| 色彩偏置 | 屏幕、纸张 | 背光色偏、饱和度异常、肤色占比偏低 | 单帧 |

### 5.2 平面性视差：单镜头拿到深度信息的关键

这一路是整个 Demo 里信息量最大的线索，也是「单目深度识别」的落点。它不需要深度
相机，用的是射影几何的一条基本结论：**一个平面在针孔相机前做任意刚性运动，两帧图像
之间的映射严格是一个 8 自由度单应矩阵**。打印照片和手机屏幕本质上都是平面，所以它们
转动时，关键点位移场可以被单应几乎完全解释，残差只剩关键点噪声。

真实人脸是非平面的三维体。转头时鼻尖、眼窝、下颌这些深度起伏大的位置会产生透视视差，
单应无法解释，残差显著更大。残差以瞳距为单位归一化，因此与人脸远近无关。

`python main.py selftest` 会把这个结论量化给你看（下面是本项目实测输出）：

```
σ = 0.3% 瞳距（实测关键点噪声底）
    绕Y转角    平面脸残差    三维脸残差    判别比
       8°      0.00500      0.01448      2.9x
      15°      0.00499      0.02569      5.1x
      25°      0.00509      0.09829     19.3x
      35°      0.00509      0.05005      9.8x
```

同时它还会标定「平面」这一侧的噪声底：对真实人脸施加已知单应变换（等价于转动一张打印
照片），此时真值残差为 0，测到的 0.0018~0.0046 瞳距全部来自关键点模型的不一致性。
`config.yaml` 里 `liveness.planarity` 的两个阈值就是据此设定的。

注意两个使用前提，界面上都会直接告诉你：头部必须转动一定角度（`require_motion_norm`），
否则残差没有信息量，线索输出「证据不足」而不参与融合；参考帧取约 0.6 秒前，太近则位移
被噪声淹没。

### 5.3 照片、屏幕、视频回放：靠什么区分

「它怎么知道是照片还是视频」的答案不在某一路线索里，而在**线索签名**上：四类载体在
七路线索上的表现各不相同，程序把当前读数与每类的期望签名做匹配，最吻合的那类就是判定。

| 线索 | 真人 | 静置照片 | 晃动照片 | 屏幕翻拍/视频回放 |
|---|---|---|---|---|
| 官方活体 CNN | 不关心 | 不关心 | 不关心 | 不关心 |
| 自然眨眼 | 有 | 无 | 无 | **有**（回放里本来就有眨眼） |
| 运动/形变 | 有 | 无 | 有 | **有**（回放里本来就有动作） |
| 平面性视差 | 高残差 | 不关心 | **低残差** | **低残差** |
| 高频纹理 | 正常 | 正常 | 正常 | **丢失**（二次采样+压缩） |
| 屏幕摩尔纹 | 无 | 无 | 无 | **有**（像素栅格指纹） |
| 色彩偏置 | 正常 | 正常 | 正常 | **偏冷/高饱和** |

这张表里藏着三个关键事实，界面板板上也会直接写出来：

1. **眨眼和运动拦不住视频回放**。回放视频里有真人的眨眼和动作，这两路会被骗。拦回放
   靠的是摩尔纹、纹理、色彩（屏幕的物理指纹）加上平面性视差（屏幕是平面）。
2. **静置照片靠眨眼和运动就能拦**：它既不会眨眼，也没有任何非刚性形变。
3. **晃动的照片是最难的一类**：它有运动、纹理清晰、还没有摩尔纹，唯一露馅的地方是
   「平面」（转动时位移场可被单应完全解释）和「没有非刚性形变」（不会眨眼张嘴）。

官方 CNN 对四类都不参与分类：它是单帧纹理判别器，在「是哪一种攻击」这个问题上不提供
信息，只参与活体/非活体的门控。

实测效果：静止照片视频被匹配为「静置打印照片」（吻合度 0.88，领先次优 0.12）并判非活体；
带眨眼和晃动的活体代理被匹配为「真人」（0.86，领先 0.31）并通过活体。界面第三列会实时
画出四类的吻合度条形图，并列出支持/反对当前判定的线索。

### 5.4 两层融合：让时间证据去门控单帧证据

融合**不是**七路加权平均，而是两层结构：

```
单帧子分 static   = 官方CNN / 纹理 / 摩尔纹 / 色彩   的加权平均
时间子分 temporal = 眨眼 / 运动形变 / 平面性          的加权平均
融合分 instant    = static × (0.35 + 0.65 × temporal)
```

这样设计有实测依据：官方 80×80 CNN 是单帧纹理判别器，实测会被一张光照良好的高清照片骗到
**0.98** 的「真人」分；而「6 秒内一次眨眼都没有」「完全没有非刚性形变」是单帧模型结构上
拿不到的证据。若做简单加权，CNN 的高权重会把照片攻击抬到阈值之上。引入时间门控后，同一
段静止照片视频的融合分从 0.65 降到 **0.37**，正确判为非活体；而带眨眼和自然晃动的活体
代理视频融合分为 **0.79**，正常通过。

`temporal` 证据不足（轨迹太短或头没动）时退化为只用 `static`，此时仍受
`min_track_frames` 与 `confirm_frames` 约束，不会立刻放行。

此外还有两道保险：`veto_below` 让强线索（官方 CNN、摩尔纹）在得分极低时一票否决；
`confirm_frames` 要求连续多帧同向才切换判决，避免门禁反复开合。

### 5.5 运行时怎么观察

识别界面里，七路线索的每一路都同时给出三样东西：归一化得分（0=攻击载体，1=真人）、
它依赖的全部原始物理量（如单应残差、峰噪比、EAR 基线）、以及一句话解释当前读数。
按数字键 `1`~`7` 可以单独开关某一路，立刻看到融合分怎么变——这是理解各路贡献最直接的方式。

## 六、人脸库存储位置与格式

人脸库在项目根目录的 `data\gallery\`（由 `config.yaml` 的 `gallery.dir` 指定）：

```
data\gallery\
├── index.json          人员索引：id、姓名、创建时间、样本数、平均检测分
├── <id>.npz            该人的 embeddings (N,512) float32 + 每条样本的姿态/质量指标
└── <id>_thumb.jpg      缩略图
```

按人分文件而不是全库一个大文件，是为了删除单人时不必重写整个库，也避免一次写坏丢掉全部
数据。`index.json` 若落后于实际文件，加载时会自动补录孤儿 npz。

## 七、界面说明

基准画布 1320×976，启动时按屏幕分辨率等比缩放（`WINDOW_NORMAL` + 屏幕尺寸自适应，
1080p 约 1.05 倍、2K 约 1.39 倍），分五个区域：

**主画面（左上 720×540）**：摄像头画面加 HUD。四角括号式人脸框颜色随判定变化；106 点
关键点按部位着色（轮廓灰、眉橙、眼绿、鼻蓝、嘴粉）；眼睛长轴与上下眼睑张口量旁标注当前
EAR；鼻尖伸出三维姿态轴；白色小点是单应预测的关键点位置，它与实际关键点之间的连线就是
平面性线索的残差——线越长越不像平面。

**P1 FFT 幅度谱（右上）**：对原始分辨率人脸 ROI 做高通后二维 FFT。红圈是检出的孤立尖峰，
即屏幕像素栅格的证据；真实皮肤的高频能量随半径平滑衰减，不会出现这种离散峰。

**P2 对齐人脸 / Laplacian / 分组残差**：ArcFace 标准 112×112 对齐裁剪（叠 106 点）、它的
Laplacian 响应热力图、以及单应残差按面部七个部位的分组柱状图——三维结构的证据集中在鼻部
和轮廓，这张图能直接看出来。

**P3 时序波形**：三行小图分别是 EAR（带基线与闭眼阈值线）、pitch/yaw/roll、以及融合分/官方
CNN 分/相似度。眨眼在 EAR 行上是一个清晰的深谷。

**底栏一**：七路线索得分条（斜纹=证据不足，白竖线=置信度）、融合仪表（半圆刻度上有阈值
刻线，并显示 static × temporal 的分解）、库内相似度条形图（带开门线与陌生人线）。

**底栏二（判决推理）**：三列。左两列逐线索给出「得分 | 实测值 | 判据阈值 | 结论」，例如
平面性一栏会写明「单应残差 0.0193 瞳距（P90 0.0460），位移 0.083；残差 <0.012→平面载体，
>0.042→三维实体」。第三列是载体类型匹配：四类候选的吻合度条形图、当前判定、支持/反对
线索，以及「静置照片 vs 真人」「屏幕/回放 vs 真人」等关键判别点的一句话说明。

运行时快捷键：`q`/`ESC` 退出，`空格` 暂停，`f` 全屏，`p` 切换性能档，`e` 弹框录入，
`m` 人脸库管理，`r` 重置轨迹，`s` 截图，`v` 切换叠加层，`1`~`7` 开关线索，`h` 帮助。

整个页面可以用鼠标操作：顶部工具栏是一排按钮（暂停/录入/管理/截图/全屏/性能/叠加/重置/摄像头）；
点击「七路线索得分」的某一行等于按对应的数字键开关该线索；点击「库内相似度」的某一行会
进入管理模式并选中该人；点击「载体类型匹配」的某一行会显示该类的期望签名。管理模式里
删除/改名/清空/录入/返回也都有对应按钮，删除与清空需要点两次确认。

管理模式快捷键：`↑/↓` 或 `w/s` 选择，`d` 删除（两次确认），`r` 弹框改名，`c` 清空全库
（两次确认），`e` 录入新人，`m`/`ESC` 返回识别。

## 八、性能与调参

### 8.1 四个性能档

管线拆成快慢两路：检测/关键点/活体每帧跑，ArcFace 特征提取在**后台线程**异步跑
（它在多会话共存时单次可达 260 ms，放在主循环里会均摊掉 30 ms）。检测在锁定人脸后只在
人脸周围的 ROI 内跑并用更小的输入尺寸——SCRFD 的耗时只由输入边长决定，ROI 里人脸占满
输入，所以更小反而更清晰。渲染侧中文文本用字形缓存绘制（整屏约两千字从 180 ms 降到 10 ms）。

| 档位 | 检测输入 | ROI 检测 | 姿态/频谱周期 | 面板 | 本机实测（含渲染） |
|---|---|---|---|---|---|
| quality | 480 | 关 | 每帧 | 全 | 5~7 fps |
| balanced（默认） | 320 | 192 | 隔 2 帧 | 全 | 9~13 fps |
| fast | 256 | 160 | 隔 4 帧 | 全 | 12~19 fps |
| ultra | 256 | 160 | 隔 4/6 帧 | 精简 | 15~25 fps |

实测值随机器负载波动较大（同一档位多次测量可差 ±40%），上表是本项目开发机（20 核 CPU、
无 GPU、内置摄像头）的范围。分析帧率与显示帧率分别显示在主画面左上角。

切换方式：启动时 `--perf fast`，运行中按 `p` 键或点工具栏「性能」按钮，立即生效。
想要极限帧率选 ultra（只保留主画面与得分条）；想要看得最全选 balanced/quality。

```bat
python main.py --perf ultra recognize      :: 最高帧率,精简面板
python main.py --perf quality recognize    :: 最稳检测,小脸/远脸
python main.py --threads 8 recognize       :: 调整 ORT 线程数
```

### 8.2 窗口：全屏与任意伸缩

窗口以 1320×998 为基准画布，启动时按屏幕分辨率等比缩放并居中；运行中可以**任意拖拽改变
大小**，画面每帧按当前窗口尺寸等比 letterbox 重采样，不会拉伸变形。按 `f` 或点工具栏
「全屏」按钮切换全屏（全屏下同样等比适配，留黑边）。

### 8.3 阈值怎么调

所有阈值都在 `config.yaml`，逐项有注释。调参的正确姿势是看数据而不是猜：

1. 运行 `recognize`，`runs\metrics_<时间戳>.csv` 会记录每帧全部原始指标；
2. 分别采集「真人」与「攻击载体」两段数据，对比各列分布；
3. 把分界点设回 `config.yaml`。面板上每个原始读数都实时可见，可以边看边调。

平面性线索有 `selftest` 自动标定；其余线索的默认值面向「笔记本内置摄像头 + 室内光照 +
人脸距离 40~80 cm」，换设备后建议按上面的流程复核。

## 九、已知限制

这些限制是方法本身的边界，不是实现缺陷，列出来是为了让你知道结论的适用范围：

- **单帧纹理类线索（官方 CNN、纹理、色彩）会被高质量打印照片骗过**，这是引入时间门控的原因；
  但一张完全静止的照片仍可能被手持晃动伪装，此时主要靠平面性视差拦截。
- **平面性视差依赖头部转动**。头不动时它输出「证据不足」；转动角度越大判别力越强
  （实测 8° 时 2.9 倍，25° 时约 19 倍）。
- **眨眼线索在采样率过低时会漏检**。低于约 6 fps 时建议降低 `det_size`。
- **视频回放攻击**（屏幕里播放真人视频）同时具备眨眼和运动，单目 RGB 很难完全防住；
  本项目靠摩尔纹与平面性视差部分拦截，不承诺完全防御。
- 强光照变化、逆光、戴口罩会同时削弱纹理与关键点质量，可能抬高误拒率。

## 十、运行产物

每次运行在 `runs\` 下生成：

- `metrics_<时间戳>.csv`：每帧全部原始指标（37 列），用于离线分析与标定；
- `events_<时间戳>.jsonl`：门禁事件流（判定、命中人、相似度、活体分、否决线索）；
- `snapshots\`：按 `s` 键保存的整块面板截图。
